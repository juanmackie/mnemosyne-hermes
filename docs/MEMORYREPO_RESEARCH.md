# Memoryrepo comparison and proposed plan

**Reviewed:** 2026-10-09 (Australia/Brisbane)  
**Upstream:** [`supermemoryai/memoryrepo` at `54f7ff3`](https://github.com/supermemoryai/memoryrepo/tree/54f7ff3065df8af687dc5c04a4bb17d6611e5fd1)  
**Local revision reviewed:** `5a1eb57cd844a2c58c5a5c5c330df04fffaca306`

This is a proposal only. No implementation is included. Upstream evidence is pinned to the reviewed commit so later changes do not silently alter the comparison.

Three review agents used `gpt-6-luna` with high reasoning, covering upstream patterns, provider fit, and lite/validation. The recommended first implementation slice is phases 0–1: characterize existing lineage, correct audit connection ownership and error reporting, and expose bounded provider inspection. Later phases depend on that result.

## Findings

Memoryrepo is a hosted application built around a per-user Git repository of linked Markdown, with chat-time edits, background “dreams,” transcript search, and a UI for notes and history. Its strongest transferable idea is inspectable, source-linked memory. It asks for one fact per line with a source reference, searches before writes, and checks cited conversations when resolving contradictions ([upstream README](https://github.com/supermemoryai/memoryrepo/blob/54f7ff3065df8af687dc5c04a4bb17d6611e5fd1/README.md#L4-L13), [memory conventions and chat instructions](https://github.com/supermemoryai/memoryrepo/blob/54f7ff3065df8af687dc5c04a4bb17d6611e5fd1/src/server/memory.ts#L41-L65), [dream process](https://github.com/supermemoryai/memoryrepo/blob/54f7ff3065df8af687dc5c04a4bb17d6611e5fd1/src/server/memory.ts#L68-L92)). Those are prompt conventions, not enforced data guarantees: the model can omit or misstate a citation.

Several of its mechanics already exist here in forms suited to Hermes and the Mnemosyne engine:

- **Search and automatic context:** upstream relies on grep and linked files ([README](https://github.com/supermemoryai/memoryrepo/blob/54f7ff3065df8af687dc5c04a4bb17d6611e5fd1/README.md#L4-L10)); our provider has engine-backed hybrid recall, filtered and budgeted prefetch, diagnostics, and an opt-in exact-query cache ([`__init__.py`](../integrations/hermes-provider/hermes_memory_provider/__init__.py#L2885), [`PATCHES.md`](../integrations/hermes-provider/PATCHES.md#L257), [`HERMES_CONFIGURATION.md`](HERMES_CONFIGURATION.md#L35)). Hermes `session_search` is already documented as the transcript fallback ([configuration](HERMES_CONFIGURATION.md#L55)).
- **Background maintenance and concurrency:** upstream’s incremental inbox/dream and conflict handling are described in its [README](https://github.com/supermemoryai/memoryrepo/blob/54f7ff3065df8af687dc5c04a4bb17d6611e5fd1/README.md#L20-L35). Our provider already has tracked engine consolidation with foreground access during inference ([`PATCHES.md`](../integrations/hermes-provider/PATCHES.md#L246)) and serialized turn sync. The memoryrepo web application also has optimistic same-file conflict detection, but its Git commit and SQLite cursor updates are not atomic ([`memory-agent.ts`](https://github.com/supermemoryai/memoryrepo/blob/54f7ff3065df8af687dc5c04a4bb17d6611e5fd1/src/server/memory-agent.ts#L316-L347), [dream commit/cursor flow](https://github.com/supermemoryai/memoryrepo/blob/54f7ff3065df8af687dc5c04a4bb17d6611e5fd1/src/server/memory-agent.ts#L358-L465)). That is not a reason to replace the engine’s SQLite transaction and lock model with Git.
- **Source/history primitives:** the provider already stores source and metadata on explicit remembers, preserves canonical slot history, records validation history, tracks native mirror ownership, and can checkpoint compression evidence ([`__init__.py`](../integrations/hermes-provider/hermes_memory_provider/__init__.py#L3477), [canonical history](../integrations/hermes-provider/hermes_memory_provider/__init__.py#L4034), [validation](../integrations/hermes-provider/hermes_memory_provider/__init__.py#L3813), [`HERMES_CONFIGURATION.md`](HERMES_CONFIGURATION.md#L62)). Turn capture is opt-in by role, and author metadata is attached when Hermes supplies it ([`sync_turn`](../integrations/hermes-provider/hermes_memory_provider/__init__.py#L3083)).
- **Lite surface:** the standalone lite CLI/MCP already has describe/bootstrap, count hints, capped cited cards, stable IDs, and card truncation ([`storage.py`](../src/mnemosyne_lite/storage.py#L1450), [`tools.py`](../src/mnemosyne_lite/tools.py#L149), [`cards.py`](../src/mnemosyne_lite/cards.py#L99)). Cards currently omit fields that are already stored, including `context` and `created_at`; the lite surface has no get-by-ID or portable export flow. Keep it separate from the Hermes provider and do not install it into the Hermes venv.

The remaining practical gap is that provider provenance and mutation history are not consistently inspectable. The append-only `AuditLog` has a query method, but it owns a SQLite connection created during provider initialization and catches query/record errors ([`audit.py`](../integrations/hermes-provider/hermes_memory_provider/audit.py#L47), [`query`](../integrations/hermes-provider/hermes_memory_provider/audit.py#L108)). A synthetic scratch check reproduced loss: recording one event on the creating thread and one from a worker resulted in two attempted events but only the first persisted. The strict engine contract currently stubs audit initialization ([`test_provider_engine_contract.py`](../tests/test_provider_engine_contract.py#L157)), so it does not catch this. The log is not exposed as a public history API and should not be described as complete, durable, or undoable. Coverage is partial: explicit remember and several tools emit audit events, but `_handle_update` does not, and turn capture, native mirrors, and background operations are not universally represented ([remember event](../integrations/hermes-provider/hermes_memory_provider/__init__.py#L3523), [`_handle_update`](../integrations/hermes-provider/hermes_memory_provider/__init__.py#L4335), [`audit.py`](../integrations/hermes-provider/hermes_memory_provider/audit.py#L69)). The explicit remember row receives source/metadata, while its audit event currently records neither ([`__init__.py`](../integrations/hermes-provider/hermes_memory_provider/__init__.py#L3512-L3526)).

Upstream source references are useful as a pattern but not proof by themselves. Its `sourceExcerpt` falls back to the end of a thread when the cited message ID is missing and labels that fallback ([`transcripts.ts`](https://github.com/supermemoryai/memoryrepo/blob/54f7ff3065df8af687dc5c04a4bb17d6611e5fd1/src/server/transcripts.ts#L91-L100)). A provider evidence lookup must return “source unavailable” for a missing exact reference; `session_search` can help locate context but cannot verify that a specific message supports the memory.

## Proposed implementation plan

### 0. Establish the source and history baseline

**Paths:** provider contract/lifecycle tests, engine contract fixtures, and this research note. Inspect the pinned engine’s lineage and existing source/history fields before assuming what survives an update, consolidation, or export. Determine what Hermes versions expose stable message references. The current contract audit covers the published 0.18.2/0.19.0 provider hooks, while newer lifecycle hooks are separately capability-gated ([`CONTRACT_AUDIT.md`](../integrations/hermes-provider/CONTRACT_AUDIT.md#L14)).

**Acceptance:** fixtures document exact behavior for remember → get → update/validate → consolidation → export, including source fields, identifiers, history retention, and visibility. Missing lineage is recorded as an unknown, not inferred. No schema changes in this phase.

### 1. Make provider inspection reliable, then expose it in the CLI

**Paths:** `integrations/hermes-provider/hermes_memory_provider/audit.py`, provider `__init__.py` and `cli.py`, their tests, and the CLI documentation. First verify whether the audit connection is safe to use from Hermes’ callback/worker threads. Replace or wrap it with a thread-safe connection strategy only if needed; make failures observable to diagnostics instead of returning an indistinguishable empty history. Add history inspection to `hermes mnemosyne` first, using stable IDs and existing engine `get`/history metadata. Keep the four core tools and their default exposure unchanged ([provider README](../integrations/hermes-provider/README.md#L20)).

**Acceptance:** tests first reproduce the current worker-thread loss, then cover the corrected connection strategy with calls from the initialization thread and background worker, injected SQLite/query failures, bounded results, and provider shutdown. The engine contract must exercise audit behavior rather than stub `_init_audit_log`. A read displays timestamp, action, ID, origin/tool, and safe metadata; it makes no completeness, durability, or undo claims. Memory reads retain existing visibility checks. Register the new test gate in [`scripts/checks.sh`](../scripts/checks.sh); `test-all.sh` already runs the Python suite, including lite tests.

Use one connection per calling thread and coordinate SQLite transactions with the established provider locking/lifecycle rules. Merely disabling SQLite's thread check is insufficient. Keep mutation logging best effort, with an observable failure counter; a failed history read must raise/report an error rather than return an empty history. Label historical coverage as partial, add an event for successful updates, and allowlist metadata rather than copying arbitrary source payloads into the log. Test foreign session/profile exclusion and deleted-memory events explicitly: joining only against live rows cannot establish access to a deleted record.

### 2. Add exact, capability-gated source references

**Paths:** provider source normalization at `sync_turn` and explicit remember, existing engine metadata only if the baseline proves it is retained, configuration/diagnostics, and lifecycle/engine contract tests. Store an exact source reference only when the Hermes host supplies a stable reference. Keep it separate from author identity and scope. Do not invent a message ID from turn order. If the source is absent, say so; transcript search may be offered as a discovery aid but is not verification.

**Acceptance:** round-trip a source reference through remember/get/history for supported host capabilities; verify references remain attached across supported updates/consolidation, remain visibility-scoped, and are absent rather than guessed on older hosts. Missing cited messages return an explicit unavailable result. No dedicated engine schema field or migration is proposed until phase 0 proves the existing metadata path insufficient.

### 3. Offer an optional Markdown evidence projection

**Paths:** provider CLI export/read code, documentation, and export tests. Generate a read-only Markdown projection from visibility-filtered engine rows, with stable IDs and available source references. Preserve the existing JSON export format. Treat Markdown as a portability and review format, not the provider’s backing store.

**Acceptance:** parse generated Markdown and compare its IDs/source references to the eligible source rows; exclude rows the caller cannot see; clearly mark missing provenance; verify JSON export compatibility. Export must not mutate the source store or use a stale cache. Generate a bounded index with detailed topic files on demand; enforce the index size in code rather than relying on a model to keep it short. Do not add Git writes, import/edit synchronization, or a second storage backend.

### 4. Consider lite inspection/export separately

Only after provider work lands, consider adding lite `inspect --id` and a portable JSONL export, plus `context` and `created_at` in cards. Use existing columns and IDs; preserve schema v3 and avoid a migration. Run the lite contract tests and add any new test to the `checks.sh` registry.

**Acceptance:** by-ID reads are namespace-safe, JSONL is stable and documented, cards surface existing metadata within current size caps, and current text/JSON/card formats remain compatible.

## Implementation gates and limits

Every future vendored edit must include a `# LOCAL PATCH:` marker, a `PATCHES.md` entry, and updated hashes/bytes/lines in `VENDORED_FROM.json`. Preserve the engine pin, single provider registration, four default tools, DB precedence, Hermes model inheritance, and provider/lite separation. Engine lineage changes belong upstream or require the existing audited engine-patch process; the plan does not create a parallel memory engine.

Run the affected audit/source/export regressions, the strict pinned-engine contract lane, `./test-all.sh --skip-llm`, `bash scripts/checks.sh`, and required pre-commit checks for implementation. Register new gates in `checks.sh`. Reuse the existing [public-prefetch evaluation](../bench/HERMES_PREFETCH_RESULTS.md) to check identity/visibility coverage, excluded operational content, and the 8,000-character ceiling. No retrieval, token-cost, or latency gain is established by this review; live gateway/model verification and engine metadata retention across consolidation remain work to prove.

## Defer or reject

- Do not adopt the hosted app’s Git-backed memory store, notes UI, separate transcript FTS index, or Durable Object scheduler. They duplicate engine/Hermes responsibilities and change the product boundary.
- Do not add OpenRouter model selection, a second model key, or upstream’s cloud dependency. This provider inherits the active Hermes model through Hermes’ local proxy; keyless operation is a repository contract ([`AGENTS.md`](../AGENTS.md#L95)).
- Do not advertise prompt-written citations as verified lineage, claim that fallback transcript excerpts prove a citation, or call the current audit log complete/undoable.
- Do not add dedicated provenance columns or migrate the engine schema before the lineage and metadata round-trip audit. Do not widen the pinned engine range as part of this proposal.
- Do not prioritize a compact profile read-model/cache. Treat the optional Honcho comparison as an experiment candidate only after source/history inspection shows a concrete latency or context gap ([provider README](../integrations/hermes-provider/README.md#L1)).
